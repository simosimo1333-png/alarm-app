## 3. コース制作 API リファレンス（コード例つき・最重要）

### 3.1 座標系とチャプター配置 `place()`

- 基本は右手系。**z が進行方向、x が横、y が高さ（絶対値）**。地面の上面は `y=0`（`islandBox` の `topY`）。
- コースを「一直線」でなく**箱庭（曲がり・分岐・立体交差）**にするため、`place(ox, oz, q)` を呼ぶと、以後に置く部品が「デザイン座標 `p` を90°単位で回して `(ox,oz)` に平行移動」した位置に置かれる。
  - `q` は 0/1/2/3（×90°のヨー回転）。`place(0,0,0)` でリセット（＝素の座標）。
  - **各ビルダーは内部で `tpos()` を通すので、`place()` 後は「そのチャプター内のローカル座標」で素直に書ける。** 方向ベクトル（速度・回転軸）は `tvec()` が回す。
- **チェックポイントとゴールも `place()` の影響を受ける値で書くこと**。ヘルパー `cpZone(cp, x0,x1, z0,z1, yMin)` はローカル矩形をワールドに変換して返す。ただし現行コードは `CP_ZONES` を**ワールド座標のベタ書き**で持っている箇所が多い（`place()` 後に手計算した値）。**新規は `cpZone()` を使うと安全**。

```js
// 例: 家の裏で東へ直角に曲げて「うらにわ」チャプターを作る
place(-37.4, 38.0, 1);   // 以後の部品は 90°回して (-37.4, 38.0) 起点に置かれる
islandBox(18, 20, 0, 0.03, 54);        // ローカル座標で素直に書ける
// ...
place(0, 0, 0);          // 次のチャプターの前に必ずリセット or 次の place を呼ぶ
```

### 3.2 基本ビルダー

| 関数 | 用途 | 備考 |
|---|---|---|
| `staticBox(w,h,d, x,y,z, mat, rotX=0, opts)` | 動かない箱（床・壁・足場） | `opts.rotY/rotZ` で回転、`opts.bounce` でトランポリン化。`x,y,z` は中心座標 |
| `islandBox(w,d, x,topY,z, topMat=grass, topH=0.3)` | 浮き島（上面＋土の断面＋底のすぼまり） | **床は基本これで作る**。下から見ても島に見える |
| `dynBox(w,h,d, x,y,z, mat, mass, opts)` | 動く箱（木箱・こわせる壁の破片） | `opts.noSleep:true`(押せる箱は必須) / `breakGroup` / `rope` / `angularDamping`。**マルチ同期される** |
| `hingedBox(w,h,d, mat, mass, pivot, localPivot, axis, angle0, opts)` | ちょうつがい（ドア・レバー・跳ね橋・カタパルト腕） | `pivot`=ヒンジのワールド座標、`localPivot`=板中心から見たヒンジ位置、`axis`=回転軸、`angle0`=初期角。`opts.motorForce` で戻す力。index を返す |
| `wallZ(z, x0,x1, yBase,h, mat, openings, th)` / `wallX(x, z0,z1, ...)` | 開口部（ドア/窓）つきの壁 | `openings:[{x0,x1,y0,y1}]`（wallXは z0,z1,y0,y1）。壁を箱の組合せで自動生成 |
| `stairs(n, rise, run, w, mat, x, y0, z0, along, dir)` | 階段 | `along:'z'|'x'`、`dir:±1` |
| `chain(from, n, spacing, opts)` | くさり・ロープ・鉄球 | `from:{anchor:[x,y,z]}` or `{idx, local:[x,y,z]}`。`opts.grip:true`(つかみやすい先端) / `opts.ball:{r,mass,mat}`(鉄球) / `opts.noStatic`(跳ね橋用)。リンクの index 配列を返す |

**マテリアル `MAT`**（単色フラット・低彩度パステル）: `grass` `dirt` `wood` `woodDark` `crate` `plaster`(白壁) `stone` `stoneDark` `roof`(くすんだ赤) `red`/`blue`(差し色ガジェット) `iron`/`ironDark` `hazard`(工事の黄) `orange` `concrete` `brick` `leaf` `gold` など。**コースのテーマ色**: おうち=wood/plaster、こうじ=hazard/orange/concrete/iron、しろ=stone/stoneDark。

### 3.3 ギミックビルダー（`GIM.*` に登録され `stepGimmicks` が動かす）

| 関数 | ギミック | ポイント |
|---|---|---|
| `gimButtonDoor(btnPos, doorHome, doorSize, openY, msg, doorMat, opts)` | 押しボタン＋スライドドア | 手（or `opts.objHit:true`で投げた箱）が触れると `door` が `openY` まで動く。`msg` は表示テキスト（**現在は null 推奨＝効果音のみ**） |
| `gimPadDoor(padPos, doorHome, doorSize, openY, msg, doorMat)` | 床スイッチ＋ドア | 重み（箱を載せる/人が乗る）で作動。**離すと閉じる**。枠の上面は床とツライチ＝箱を押して載せられる |
| `gimLever(x,y,z, angle0, opts)` | レバー（ヒンジ棒） | `opts.baseY` で支柱の根元高さ。index を返し、`GIM.lifts` の `leverIdx` に使う |
| `hangingBridge(x,y, z0,z1, w, n, mat)` | ゆれるつり橋 | 板を n 枚並べ、左右2点のP2P拘束を `initPhysics` が張る |
| `spinnerDisc(x, topY, z, r, omega, mat)` | 回転する床 | 乗った人も一緒に回る。`omega` は角速度（±で逆回転） |
| `moverBox(size, home, axis, amp, omega, phase, mat)` | 往復する足場・ゆれる鉄骨 | **時刻決定的**（ホスト/ゲストでずれない）。`axis:'x'|'z'`、`amp`=振幅、`omega`=角速度 |

**リフト/ゴンドラ/おもりエレベーター**は専用ビルダーがなく、`kinObject` でメッシュを登録してから `GIM.lifts` / `GIM.balances` に手で push する（§6.2 のコード参照）。

**カタパルト・跳ね橋**は `hingedBox` + `chain` を組んでから `GIM.catapults` / `GIM.drawbridges` に push（§6.3 参照）。

### 3.4 `initPhysics`（1853〜）が拘束を張る対象

`buildCourse*` はメッシュと `dynObjects`/`GIM` の**定義**を作るだけ。実際の cannon-es 剛体と拘束は**ホストがゲーム開始時に** `initPhysics` で生成する。ここが以下を処理する:
- `dynObjects` の各要素 → 剛体（box/sphere）。`hinge` があればヒンジ拘束、`rope` チェーンは隣接リンクを距離拘束で連結。
- `GIM.chains` のアンカー固定、`GIM.plankBridges` の板の左右P2P拘束。
- **新しい種類の拘束を足すときはここに追記が必要**。既存のギミック種（ヒンジ・チェーン・つり橋）を使う限りは追記不要。

### 3.5 `stepGimmicks`（2006〜）が毎フレーム動かす

`GIM.buttons`(ボタン) `GIM.pads`(床スイッチ) `GIM.lifts`(リフト/ゴンドラ) `GIM.balances`(おもりEV) `GIM.spinners` `GIM.movers` `GIM.drawbridges` `GIM.catapults` `GIM.breakables`(こわせる壁) `GIM.rods`(見た目のワイヤ) `GIM.stars`/`GIM.floaters`(飾りの回転/浮遊) を更新。**ホスト権威**（ホストだけが物理を進め、結果を配信）。

**摩擦の重要な注意**: cannon-es の箱同士の接触摩擦が設定値より過剰に効き「箱が押せない」問題があったため、**オブジェクト-床の摩擦を0にして `stepGimmicks` 内でクーロン型の疑似摩擦（毎ステップ一定減速）を掛けている**。押せる箱には `noSleep:true` が必須（スリープすると低速push で起きないデッドロックになる）。

## 4. キャラ性能の設計制約（レベルデザインの前提数値）

`fallflat.js` 冒頭の定数。**これらを前提に「登れる/跳べる/届く」を設計する**。キャラ側は基本いじらない前提。

| 数値 | 値 | レベルデザインへの意味 |
|---|---|---|
| 歩行速度 `WALK_SPEED` | 3.4 m/s | もっさり。長い直線は退屈になるので曲げる |
| ジャンプ到達高 | **約0.97m**（`JUMP_SPEED=4.8`） | **0.9m 程度の段差はジャンプで越えられる** |
| よじ登り可能高さ | **1.0〜1.8m** | 掴んで登れる範囲。**よじ登り必須壁は 1.3〜1.5m が標準**（ジャンプ0.97mでは絶対届かない高さ） |
| よじ登り実績上限 | 1.95m（コース1のロフト） | これ以上は非推奨 |
| よじ登り所要 | 1.5〜2.5秒（入力駆動） | **下を見ながら前進し続けている間だけ登る**。掴んだだけでは登らない |
| 手のリーチ `HAND_REACH` | 0.95m | 掴める距離。くさりの先端 `grip` はここに届く高さに吊るす |
| ジャンプ`GRAVITY` | -11 | ふわっとした落下 |
| 持てる箱の質量 | 3〜12.5 | **これ以下なら両手で抱えて運べる**。鉄球(14)・岩(30)は重すぎて持てない＝スイング/転がし用 |
| ハード落下閾値 `HARD_FALL_V` | 7.5 m/s | これより速く落ちて着地すると 0.8秒ラグドール脱力 |
| 落下復帰 `RESPAWN_Y` | -2.4 | これより下に落ちると最終CPの上空 `SKY_DROP`(13m) から降ってくる |
| アイテム復帰 `FALL_Y` | -8 | 動く物がこれより下に落ちると `home` へ復活（ヒンジ連結物は落ちない） |

**よじ登り必須ポイントの作り方**:
- 高さ 1.3〜1.5m の `staticBox` を島の幅いっぱいに置く（迂回されないように）。
- **周囲に踏み台になる箱・段差を置かない**（置くとジャンプで越えられてしまい「必須」でなくなる）。
- 直前に必ずチェックポイントを置く（落下時のストレス軽減）。
- 二段登り（例: 1.5m→1.3m連続）で難度を上げられる（コース3のべっかん基壇）。

## 5. マルチプレイ同期の制約

- **ホスト権威**: ホストが全 `dynObjects` の剛体を物理シミュレーションし、20Hz(`SNAP_MS`)で位置+姿勢のスナップショットを配信。ゲストは補間表示（`INTERP_DELAY=130ms`）。
- したがって **`dynBox`/`hingedBox`/`chain`/`kinObject` で作った動的・キネマティック物は自動的に同期対象**。特別な対応は不要。
- **kinematic な動き（spinner/mover/lift）は時刻決定的にすること**。`moverBox` は時刻から位置を計算するのでOK。ランダムを使うなら `makeRng(seed)` でシード固定（`isletDeco` の飾り小島がこれ）。
- ゲストは**コース番号から同じ `buildCourse*` を実行**して同一レベルを構築する。だから乱数・時刻依存以外は完全に決定的でなければならない。
- 剛体数バジェット: 同時アクティブはおよそ40以下。遠いチャプターの動的物は自然にスリープする（`noSleep` を付けるのは押す必要がある箱だけ）。こわせる壁の破片は多いので `breakGroup` でまとめてスリープ管理。

## 7. 設計原則（`docs/research-hff.md` の要約＋実装で学んだこと）

1. **箱庭・複数解**: 一直線にしない。正攻法（安全だが長い）と力技（危険だが短い）の2ルートを常に用意し、必ず合流させる。
2. **よじ登り必須点**を各コースに散らす（§4の作り方）。ジャンプ区間・よじ登り区間・パズル区間・移動ギミック区間が**交互に来るリズム**にする。
3. **難易度勾配** C1 < C2 < C3。C1は学習曲線（前半チュートリアル、後半応用）。
4. **CP密度**: 難所（よじ登り・跳ね橋・大ギャップ）の直前に必ず1つ。分岐の合流点にも1つ。マルチでは誰か1人が踏めば全員有効。
5. **寄り道とごほうび**: 進行に不要な小島に金の星・大きな物理玩具を置く（`goldStar`/`bounceShroom`）。遊べる物を置くだけでよい。
6. **ランドマーク**: 遠くから見える構造物を軸に動線を回す（気球・クレーン・天守）。
7. **見た目**: `MeshLambertMaterial` 単色・低彩度パステル・浮き島（`islandBox`）・ローポリ雲・ソフト影。テクスチャは使わない方が「らしい」。

## 8. 既知の落とし穴（実際に踏んだもの・必ず読む）

- **cannon-es の箱摩擦が過剰** → オブジェクト-床の摩擦は0、`stepGimmicks` の疑似摩擦で代用。押せる箱は必ず `noSleep:true`。
- **トンネリング（壁抜け）**: 速い剛体・強い力で1ステップの移動が壁厚(0.5m〜)を超えると貫通する。力・速度はクランプ。よじ登りは位置直接セット（テレポート）を廃止し連続的な力で実装済み（キャラ側）。**壁は薄すぎない（`th` 0.3以上推奨）**。
- **`place()` 後の座標**: ビルダーはローカル座標で書けるが、**CHECKPOINTS/CP_ZONES/GOAL をワールド座標でベタ書きしている箇所がある**。`place()` 内で作った難所のCP矩形は手計算がずれやすい。**新規は `cpZone()` を使うか、検証で必ずCP通過を確認**。
- **Editツールのマッチ**: 日本語の全角括弧「（）」が絡む行は文字列マッチが崩れやすい。行範囲のスプライスや十分な文脈での置換を。
- **ヘッドレス検証の時間**: Playwright headless は rAF が約10fps でシム時間が実時間の約1/4しか進まない。**待ち時間を長めに取り、時刻でなくポーリング（物理状態の変化）で判定**する。実ブラウザでは60fps。
- **つり橋の板間隔**: 板が浮いて入口で詰まる/隙間に落ちる問題があった。アンカーを床とツライチに、板幅を隙間最小に。
- **跳ね橋が下りきらない**: くさりに `noStatic:true` を付けないと静止摩擦で止まる。橋幅・開放判定角(`th`)も要調整。

## 10. 次のタスク「コース延長」への具体ガイド

**目標**: コースをもっと長く。ユーザーは「短く直線的でつまらない」→箱庭化で改善済みだが、さらに延長を希望。

**安全な継ぎ足し方**:
1. **末尾に新チャプターを追加**するのが最も安全。各コースのゴール手前（合流後）に `place()` で新しい起点を作り、既存の座標とぶつからない方向（空きのある x/z）へ伸ばす。**ゴールの `staticBox`/`goalFlag`/`GOAL` を新しい終端へ移設**し、CP を末尾に足す。
2. **既存分岐を延長**するのも良い。分岐ルートをもう1段深くして、より遠くで合流させる。
3. **座標空間の空き**: 各コースは §6 の範囲を占有。飾り小島 `isletDeco` の矩形（各 build 末尾）が「動線が通らない空き領域」の目安になる。そこを新チャプターに転用すると空が埋まる分は `isletDeco` を減らす。
4. **やってはいけないこと**:
   - 既存のクリア済みフロー（ギミックの成立条件・よじ登り高さ）を壊す変更
   - CHECKPOINTS の並び順を崩す（CP は昇順に踏む前提。`zn.cp > doll.cp` で前進判定）
   - GOAL を移設したのに CP/GOAL 座標の更新を忘れる（踏破不能になる）
   - キャラ・入力・カメラ・ネットワーク層への変更（§2「触らない」範囲）
   - マルチ非同期な要素（時刻/シード以外のランダム、ホスト以外での物理変更）
5. **新ギミックを足したい場合**: 既存の `hingedBox`/`chain`/`spinnerDisc`/`moverBox` の組合せで大抵作れる（シーソー橋=ヒンジ、ターザン=chain grip、回転床=spinner、動く足場=mover）。全く新しい拘束が要るときだけ `initPhysics` と `stepGimmicks` に追記。**追記したら必ずマルチ同期を検証**。
6. **バランス**: 延長で単調にならないよう §7 のリズム（ジャンプ/よじ登り/パズル/移動ギミックの交互）を保つ。延長分にも寄り道1つ・CP を難所直前に。

**着手の型**:
```js
// buildCourse1 の末尾、goalFlag の前あたりに新チャプターを挿入する例
place(NEW_OX, NEW_OZ, Q);          // 空いている方向へ
islandBox(...);                    // 新しい島
// ... ギミック・よじ登り点・寄り道 ...
place(0,0,0);                      // 元に戻す or 次のチャプター
// goalFlag と GOAL を新しい終端座標へ移す
// CHECKPOINTS に末尾のCPを追加、CP_ZONES に対応ゾーンを追加
```
延長後は §9 のチェックリストを最初から最後まで通すこと。
