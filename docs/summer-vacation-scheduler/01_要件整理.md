# 夏休み調整アプリ — 要件整理(Phase 1)

- 作成日: 2026-07-16
- ステータス: ドラフト(議論の過程で更新される前提)
- 目的: 企画書作成に向けて、現時点の要件・前提・未確定事項を整理する

---

## 1. 背景と課題

### 現状のやり方
- 空のカレンダーを印刷し、各自が手書きで夏休みの希望を記入している。

### 現状の課題
| 課題 | 具体的な困りごと |
|------|------------------|
| 見えづらい | 紙は1枚しかなく、その場に行かないと全体状況がわからない |
| 申請しづらい | 他の人の希望や業務予定が見えないため、遠慮したり出し直しになったりする |
| 共有できない | 紙のため、リモートや外出中のメンバーと状況を共有できない |
| 更新が大変 | 書き直し・消し込みが煩雑で、最新状態の維持にコストがかかる |

### なぜ取り組むのか
夏休みの調整状況が「見えづらく、申請しづらい」状態を解消し、
全員が全体を見ながら気持ちよく希望を出し合える状態をつくる。

---

## 2. ゴール

### 目的
夏休み(夏季休暇)の希望調整を、紙のカレンダーからアプリに置き換えて
**効率化・見える化・共有可能** にする。

### 成功基準(KPI)
- **数値的KPI**: 設定しない(現時点)
- **質的KPI**:
  - それぞれの大きな業務の予定が一覧できること
  - 各自の休みの希望が **希望の程度つき** で入力・閲覧できること
  - → 「この日は◎の人が2人いるな」「この週は繁忙だから避けよう」が一目でわかる状態

---

## 3. 利用者と利用シーン(確定事項)

ヒアリングにより以下が確定した。

| 項目 | 決定内容 |
|------|----------|
| 利用規模 | **約10人のチーム × 2チーム**(計 約20人) |
| 希望の程度 | **3段階**(例: ◎=絶対休みたい / ○=できれば休みたい / △=候補) |
| 確定の方法 | **全員で見ながら自主調整**(アプリは見える化まで。確定権限を持つ管理者は置かない) |
| 利用環境 | **スマホ・PC両方**(入力はスマホ、全体確認はPCなどの併用を想定) |

### 想定される利用の流れ(To-Be ワークフロー)
1. カレンダー(夏休み対象期間)をアプリ上に用意する
2. 各メンバーが自分のスマホ/PCから、休みたい日に ◎○△ を入力する
3. 大きな業務予定(締切・イベント・繁忙日など)もカレンダー上に登録する
4. 全員が同じカレンダーを見て、重なりや業務予定を確認しながら自主的に調整する
5. 調整がついたら各自が希望を「確定」状態に更新する(※確定の扱いは要議論)

### 得られる価値
- いつでもどこでも最新の調整状況が見える(紙の場所に行かなくてよい)
- 希望の「程度」が見えるので、譲り合い・調整の会話がしやすくなる
- 業務予定と休み希望を同じ画面で見られるので、判断が速くなる

## 4. MVP 機能要件(案)

### 必須(これがないと紙の代替にならない)
| # | 機能 | 内容 |
|---|------|------|
| F1 | カレンダー表示 | 対象期間(例: 7〜9月)を月表示。全員の希望と業務予定を重ねて表示 |
| F2 | 休み希望の入力 | 日を選んで ◎○△ の3段階で入力。自分の希望はいつでも変更可能 |
| F3 | メンバー・チーム | 約20人を2チームに分けて登録。チームで絞り込み表示できる |
| F4 | 業務予定の登録 | 大きな業務予定(締切・イベント等)を誰でも登録でき、カレンダーに表示 |
| F5 | 共有 | URL を知っているメンバー全員が同じ画面を見られる |
| F6 | マルチデバイス | スマホ・PC どちらでも入力・閲覧できる(レスポンシブ対応) |

### あると良い(MVP に入れるか要議論)
| # | 機能 | 内容 |
|---|------|------|
| F7 | 日別サマリー | ある日をタップすると「誰が◎/○/△か」「業務予定」が一覧できる |
| F8 | 希望の理由メモ | 「子どもの行事」などの短いコメントを希望に添えられる |
| F9 | 確定マーク | 調整がついた休みを「確定」として区別表示する |
| F10 | 重なりアラート表示 | 同じ日に休み希望が集中している日を色などで強調する |

### MVP の対象外(候補 — 要確認)
- ログイン・パスワード管理(名前選択式などの簡易運用で開始する案)
- 承認ワークフロー(申請→上長承認のような機能。「自主調整」方針のため不要と想定)
- 通知機能(メール・プッシュ通知)
- 夏休み以外の休暇(有休全般)への対応 → まずは夏休み専用
- 勤怠システム連携・出力

## 5. 画面イメージ(ラフ)

```
┌─────────────────────────────────────┐
│ 夏休み調整 2026        [チームA|チームB|全員] │
├─────────────────────────────────────┤
│  ◀ 2026年8月 ▶                       │
│ ┌───┬───┬───┬───┬───┬───┬───┐        │
│ │日 │月 │火 │水 │木 │金 │土 │        │
│ ├───┼───┼───┼───┼───┼───┼───┤        │
│ │   │ 3 │ 4 │ 5 │ 6 │ 7 │   │        │
│ │   │◎2 │   │📌締切│◎1 │○3 │   │      │
│ │   │○1 │   │   │△2 │   │   │        │
│ └───┴───┴───┴───┴───┴───┴───┘        │
│  8/3 の詳細:                          │
│   ◎ 田中・佐藤   ○ 鈴木              │
│   📌 A社納品 締切                     │
├─────────────────────────────────────┤
│ [自分の希望を入力] (名前: 田中 ▼)      │
└─────────────────────────────────────┘
```

- カレンダーのマスには「◎○△ の人数」と業務予定(📌)を集約表示
- 日をタップ/クリックすると誰の希望かの詳細が見える(F7)
- 入力モードでは自分の名前を選び、日をタップして ◎→○→△→なし を切り替え

## 6. データの考え方(概要)

| データ | 主な項目 |
|--------|----------|
| メンバー | 名前、所属チーム(A/B) |
| 休み希望 | メンバー、日付、程度(◎/○/△)、(メモ)、(確定フラグ) |
| 業務予定 | 日付(または期間)、タイトル、対象チーム(A/B/全体) |
| 設定 | 対象期間(開始日・終了日)、年度 |

※ 全員で共有するため、データはブラウザ内保存ではなく **サーバー側に保存** が必要。
実装方式(どのサービスを使うか)は Phase 2 の技術選定で決める。

## 7. 未確定事項(次に決めたいこと)

| # | 論点 | 選択肢の例 |
|---|------|-----------|
| Q1 | 対象期間はいつからいつまでか | 7/1〜9/30 / 8月のみ / 毎年設定できるようにする |
| Q2 | 1人あたりの夏休み日数のルールはあるか | 例: 5日間・連続必須かどうか。あるなら「残り日数」表示が有効 |
| Q3 | 同じ日に休める人数の上限はあるか | あるなら超過日を警告表示(F10 の具体化) |
| Q4 | メンバー登録は誰がするか | 管理者役が最初に一括登録 / 各自が自分で名前を追加 |
| Q5 | 本人以外の希望を編集できてよいか | 自由(性善説) / 自分の分のみ(簡易ロック) |
| Q6 | 業務予定はチーム単位か全体か | チームごとに色分け表示するか |
| Q7 | 「確定」の扱い | 確定マーク(F9)を MVP に入れるか、運用でカバーするか |
| Q8 | 社外からのアクセス | 自宅・移動中からも使うか(URL 共有のセキュリティ方針に影響) |
