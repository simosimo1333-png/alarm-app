## 1. 何をつくるか(一言で)

紙のカレンダーで行っている夏季休暇の希望調整を、**スマホ・PCから全員で見られるカレンダーアプリ**に置き換えます。

## 2. 背景と課題

現在は空のカレンダーを印刷し、各自が手書きで希望を記入しています。このやり方には次の問題があります。

- **見えづらい**: 紙は1枚しかなく、その場に行かないと全体状況がわからない
- **申請しづらい**: 他の人の希望や業務予定が見えず、遠慮や出し直しが発生する
- **共有できない**: 外出中・リモートのメンバーと状況を共有できない

## 3. 対象と前提ルール

| 項目 | 内容 |
|------|------|
| 利用者 | 2つの課、計約20人(各課: 課長1・係長1・係員約8) |
| 休暇 | 夏季休暇 **1人3日**、対象期間 **7月〜10月** |
| 体制ルール | 同じ課の課長と係長は同日休みに要確認。各課の係員は最低1人在席 |

## 4. 解決策(アプリの主要機能)

1. **みんなのカレンダー** — 全員の休み希望と大きな業務予定を1つのカレンダーに重ねて表示。課で絞り込み可能
2. **3段階の希望入力** — ◎(絶対)/○(できれば)/△(候補)で希望の程度を表現。候補は3日を超えて出してよい
3. **確定と残り日数** — 調整がついた日を本人が「確定」にする(上限3日)。残り日数は自動計算
4. **ルール警告** — 課長×係長の重複日、係員の在席が0人になる日をカレンダー上に⚠表示。確認は従来どおり口頭で行う(承認機能は持たない)
5. **本人のみ編集** — 個人ごとの4桁PINで、自分の希望だけを編集できる
6. **スマホ・PC両対応** — 入力はスマホから、全体確認はPCの大画面でも

## 5. 期待される効果

- いつでもどこでも最新の調整状況が見える(紙の場所に行く必要がなくなる)
- 希望の「程度」と業務予定が同じ画面で見えるため、譲り合い・調整の会話が速くなる
- 残り日数・体制ルールの確認が自動化され、調整ミス(在席0人など)を防げる

## 6. やらないこと(今回のスコープ外)

- 承認ワークフロー(申請→上長承認)— 全員で見ながらの自主調整という運用方針のため
- 通知機能、夏休み以外の休暇への対応、勤怠システム連携
- 組織階層の管理(**部>課>係** の追加・削除)— **完成後の将来拡張**として対応予定。後から拡張しやすいよう、設計段階で組織をデータとして持たせておく

## 7. 進め方

| フェーズ | 内容 |
|----------|------|
| Phase 1 | 要件整理(完了)|
| Phase 2 | 画面設計・技術選定(データの保存先を決定)|
| Phase 3 | MVP実装・チーム内トライアル |
| Phase 4 | フィードバック反映・本番運用 |
| Phase 5 | 将来拡張(部>課>係の組織階層管理)|

## 8. 留意点

- 本人確認は簡易な4桁PINのため、厳密なセキュリティ用途ではなく「誤編集・なりすまし防止」レベルの位置づけ
- URLを知っていれば閲覧できる共有方式のため、掲載する業務予定の内容は社外秘レベルに応じて運用で調整する
